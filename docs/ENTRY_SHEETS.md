# 出展団体の一括記入シート（段階 1〜2）

出展団体に記入用スプレッドシートを 1 つずつ配り、提出された内容を主催スプシへまとめて取り込む仕組み。
設計の背景と項目の一覧は設計メモ（HOPPING FES の記入シートが土台）を参照。

## 使い方（主催）

各シートには上から順に押せるボタン（図形へ割り当てる関数）の案内が配置されているため、メニューを探さず手順通りに進められる（同じ操作はメニュー「タイムテーブル連携」からも実行可能）。詳しい流れや図解・色の見方は自動生成される「Readme」シートを参照。

1. `scripts/gas/Code.js` を主催スプシの Apps Script に貼り替え、スプシを開き直す
2. 初期セットアップ（`setupDraftSheet` または `entrySetupSheets`）
   - 左から手順順に **`Readme` → `1.設定` → `2.団体一覧` → `3.公演かんたん入力` → `4.公演一覧` → `運営用連絡先` → `取り込み履歴` → `利用レポート`** のタブ順・色分けで自動整備される（古いシート名 `設定` / `団体一覧` / `1.公演かんたん入力` / `2.公演一覧` 等がある場合は自動でリネーム・データ維持）
3. 「`1.設定`」を書く（STEP 1）
   - **会場のモード**：`1つの建物`（部屋をプルダウンで選んでもらう）／`複数の建物`（会場名と住所を書いてもらう）
   - **会場の部屋一覧**（1つの建物のとき）：`ホール, 第1会議室, 第4会議室` のように `,` 区切り。会場マップの部屋名と同じにする
   - **難易度の表し方**：`1〜10`（既定）／`1〜5`／`★1〜★5`／`初級・中級・上級`／`使わない`（記入用シートの難易度欄自体を省き、一覧には `-` を出力）
   - **公演形式の選択肢**・**記入の締切**
   - **保存先フォルダ**：記入用シートと素材フォルダを作る場所（ドライブのフォルダの URL）。空欄なら主催スプシと同じフォルダ
4. 「`2.団体一覧`」に、1 公演につき 1 行で団体名と担当者のメールアドレス（Google アカウント）を書く（STEP 2）
5. 【出展団体】記入用シートを作る（ボタン：`entryCreateSheets`）
   - 作る前に、保存先と件数を見せて確かめる（「いいえ」で止まる）
   - `<保存先>/出展団体_<イベント名>/記入用シート`・`…/素材` に、団体ごとの記入用シートと素材フォルダ（ポスター画像を入れる）を作り、担当者に編集権限で共有する
   - マイドライブの直下には作らない。同じ名前のフォルダがあれば使い回すので、何度押してもフォルダは増えない
   - 「記入用シート」の列のリンクを各団体に知らせる
   - 内部用の管理列（シートID・フォルダID・指紋）は自動で非表示になる
6. 【出展団体】記入状況を確認する（ボタン：`entryRefreshStatus`） …… 未着手／記入中／提出済み／提出後に変更あり／取り込み済み（要確認 N か所）、と未記入の項目が出る
7. 【出展団体】全団体から取り込む（ボタン：`entryImportAll`）
   - 「提出する」にチェックがあり、必須が埋まっている分だけ取り込む
   - 公開する情報 → 「`3.公演かんたん入力`」（右側に補足列・`回ごとの定員` を含む。内部列は非表示）／連絡先 → 「`運営用連絡先`」（公開データに出ない）
   - 前回から変わった所 → 「`取り込み履歴`」
   - 「要確認」が残っている場合は、`3.公演かんたん入力` を確認した上で必要に応じてボタン（`entryClearCheckMarks`）で一括確認済みにできる
8. 「`3.公演かんたん入力`」で全体を確認・調整し、ボタン（`expandDraftToTimetable`）で「`4.公演一覧`」へ展開（STEP 3〜4）
   - 記入用シートの「回ごとの定員」が空でない回は、「`4.公演一覧`」の該当回の `定員` 列へ反映される（それ以外の回は基本の「1回あたりの定員」を使う）
   - 「`4.公演一覧`」の右側・補足列は折りたたみ可能で、ボタン（`manualExportJsonToGitHub`）から Web 公開データを同期する（当日運用）

差し替えは、団体が同じ記入用シートを直すだけ。主催がもう一度【全団体から取り込む】を押すと、その団体の行に反映される。

### 主催の手直しは消えない（セルごとの合わせ方と色分け）
主催は、団体の書き間違いを「`3.公演かんたん入力`」でそのまま直してよい。取り込みのたびに、団体の値を隠しシート「_取り込み控え」に残しておき、次の取り込みでセルごとに 3 つを比べる。

| 前回の団体の値と比べて | 結果 |
|---|---|
| 主催だけが直した | 主催の値を残し、セルを **水色**（`#dbeafe`）にしてメモに「【主催が修正済】団体の記入値：…」を残す（履歴にも出さない） |
| 団体だけが直した | 団体の値にする（履歴に「反映」） |
| 両方が別の値に直した | 主催の値を残し、セルを **濃い黄色**（`#fde68a`）にして「【取り込み・要確認】」と団体の値をメモに書く（履歴に「要確認」）。「`2.団体一覧`」の状態にも「要確認 N か所」を表示 |
| 両方が同じ値に直した（または主催が団体の値に揃えた） | 変更なし。付いていた「要確認」や「主催が修正済」の印（色とメモ）も自動で外れる |

主な仕様と運用ルール：
- 行はその場で直す。主催が並べ替えた順番や、変わっていない列は触らない
- 主催が **1 行分だけ** 日程セルを未知の日程へ書き換えた場合（曖昧さが無い場合）は、重複追加せず元の行と 1 対 1 で結び付け、主催の日程を残す（複数行同時に未知の日程へ書き換えた場合は従来通り「要確認」として残す）
- 団体がやめた日程の行は消す。主催が直していた行なら「要確認」
- 主催が行を消した場合は入れ直す。公演を取りやめるときは「`2.団体一覧`」からその団体の行を消す
- 「要確認」が残っていても、主催がそのまま値を使うなら「【出展団体】『要確認』の印を消す」（`entryClearCheckMarks`）で一括解除できる
- 主催が「`3.公演かんたん入力`」に手で入れた行（取り込み元の列が空の行）は、取り込みで消えない
- 旧方式の Googleフォーム関連関数（`createEntryForm` / `importFormResponsesToDraft`）は削除済み

## 守っていること

- 担当者名・メール・電話・運営への連絡事項は「`運営用連絡先`」にだけ入る。公開データ（`4.公演一覧`・`data.json`）を作る処理はこの表を読まない
- 「取り込み元(記入用シートID)」「回ごとの定員」「【…】ボタン案内列」および「`1.設定`」シートのセクション見出し行（`■` / `▼`）は公開データに出さない
- 時刻セル（`Date`）はスプレッドシートのタイムゾーン（`Utilities.formatDate`）を使って `"HH:mm"` に統一する
- 記入用シートは担当者の Google アカウントにだけ共有する（リンクを知っている人全員には開かない）
- 素材フォルダの画像は、取り込み時に「リンクを知っている人は閲覧可」にする（タイムテーブルに表示するため）
- 主催用 `Readme` と出展者用 `はじめに` の色ルールを統一している（`#fff4b8`＝入力、`#dbeafe`＝主催修正済、`#fde68a`＝要確認、`#fde2e2`＝非公開、`#f1f5f9`＝自動・記入例・管理用）

## テンプレート管理者向け：初回セットアップ＆図形ボタン割り当て一覧

主催へテンプレートスプレッドシートを渡す前に、管理者側で Apps Script の貼り付け・初期セットアップ・図形ボタンの配置を行います。主催向けの `Readme` シートには英語の関数名を出さず、この一覧で管理します。

1. 拡張機能 → Apps Script に `scripts/gas/Code.js` を貼り付けて保存し、スプレッドシートを再読み込みする
2. メニュー「タイムテーブル連携」→ **「【初回】全シートをセットアップ（Readme含む）」**（`setupDraftSheet`）を 1 回実行する
3. 各シートの案内セルの横・上へ「挿入 → 図形描画」でボタンを作成し、以下の関数を割り当てる（「⋮」→「スクリプトを割り当て」）

| 順 | 配置するシート＆位置 | ボタンの表示名（例） | 割り当てる関数名 | 用途 |
|---|---|---|---|---|
| ① | `1.設定`（任意 / 初回のみ） | 初期セットアップ / Readme更新 | `setupDraftSheet` / `refreshReadmeSheet` | 全シート・`Readme` を整え直す |
| ② | `2.団体一覧`（`M1` 案内横） | 記入用シートを作る | `entryCreateSheets` | 未作成分の団体記入用シートと素材フォルダを作成・共有 |
| ③ | `2.団体一覧`（`O1` 案内横） | 記入状況を確認する | `entryRefreshStatus` | 提出状況（未着手・変更あり・要確認件数など）を更新 |
| ④ | `2.団体一覧`（`Q1` 案内横） | 全団体から取り込む | `entryImportAll` | 提出済み・必須入力完了の団体を取り込む |
| ⑤ | `3.公演かんたん入力`（`C1:E1` 上部バー） | 要確認の印を消す | `entryClearCheckMarks` | 濃い黄色の要確認印（色とメモ）を一括解除 |
| ⑥ | `3.公演かんたん入力`（`F1:H1` 上部バー） | `4.公演一覧` へ反映＆Web公開 | `expandDraftToTimetable` | `4.公演一覧` へ展開して `data.json` を同期 |
| ⑦ | `4.公演一覧`（見出し右端） | Web公開データを同期 | `manualExportJsonToGitHub` | 当日の完売設定や `1.設定` 変更だけを即時公開 |

- **図解イラストの読み込み元**：`Readme` シートと出展者用 `はじめに` シートの図解イラストは `README_IMAGE_BASE_URL` 経由で `docs/images/readme-organizer-flow.png` および `docs/images/readme-exhibitor-flow.png` を `=IMAGE(...)` で表示します（GitHub の `main` ブランチへプッシュ後に Google スプレッドシート上で画像が表示されます）。
- **テスト用コピーの注意**：本番サイトの上書きを防ぐため、テスト用スプレッドシートでは「`1.設定`」の `GitHubリポジトリ` を必ず空欄にしておきます。

## 検査

```bash
node --test tests/gas-entry.test.js       # 記入内容 → 行の組み立て・モード・難易度・回ごとの定員・差分・時刻・状態・公開範囲
node --test tests/gas-entry-flow.test.js  # スプシとドライブをまねた環境で、準備から公開データ・要確認解除・難易度プリセットまで通しで動かす
```

まねた環境で確かめられるのは、行と列の位置・振り分け・差分・ハイライト色/メモ・公開範囲まで。
共有・権限・入力規則の実際の効き方、ボタン（図形）の見た目、実行時間（6 分の上限）は、本物のスプシで試す必要がある。
記入用シートを作る処理は 4.5 分で止まり、残りはもう一度実行すれば続きから作る。
