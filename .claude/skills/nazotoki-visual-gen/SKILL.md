# 謎解きビジュアル生成スキル

## 目的
「いかにも AI が作った」と分かるビジュアルを避け、**謎解きの公演だからこそ成立する**ポスターを作る。
判断に迷ったら常に問う：**「これは他のどんな案件にも当てはまる無難な答えになっていないか？」**

## 基本方針（過去の失敗から決まったこと）
1. **画像生成で絵を作らない。図形と文字をコードで描く。**
   - 画像生成の出力は、配色を変えても同じモデルの癖（グロー、光の筋、中央一点透視、隅々までの描き込み）が残った
   - モチーフ単体の生成に絞っても、指示と違う形（王冠形でないプリン、商店街のアーチではなく鳥居）が出た
   - 取得工程（デザイン化→書き出し）でも白紙ページの混入や上端の切れが起きた
2. **文字組みが先、モチーフは後。**（ui-spellbook『TYPOGRAPHIC FLOW』：「キャラクターを先に置き、余白へ文字を配置してはならない」）
3. **モチーフ自体を小さな謎にする。** 図形が「解ける」ことで、謎解きのポスターである意味が生まれる
4. **系統を散らす。** 並べたとき同じ作者に見えないよう、図形の作法・書体・レイアウトを 1 枚ずつ変える

---

## Phase 1: アートディレクション（`spec.json` に書く）

1枚ごとに以下を決める。ここを飛ばして描かない。

- **Family（図形の作法）**: 下表から 1 つ。同じセットの中で重複させない
- **Puzzle（謎）**: 図形を読み解くと答えになる仕掛け。**実際に解けること**（解読表・対応表など必要な鍵を画面内に置く）
- **Type**: 書体（Google Fonts）・行ごとの大きさ・字下げ・色。行の途中では折り返さない
- **Colors**: 紙色＋インク 2〜3 色。グラデーション不可
- **Layout**: 文字の位置を先に決め、モチーフの枠（slot）はその残りに置く

| Family | 実装（motifs.mjs） | 謎の例 |
|---|---|---|
| 影絵（光る幕に黒い形） | `pigpen` | ピッグペン暗号＋解読表 |
| 色紙の切り貼り | `legend` | 図形＝カナの対応表で並びを読む |
| リソ2色の網点 | `dotword` | 網点に別色の点で隠した文字 |
| 巨大タイポ（昇る文字） | `rising` | 床から上半分だけ見える文字 |
| 校正紙（トンボ・赤字） | layout `proof` ＋ `{誤|正}` 記法 | ポスター自身が赤字で直されている |
| 切り絵（紙の層と影） | `soda` | テーブルに映る逆さ文字 |
| 路線図・街区 | `route` | ルート順に駅を巡ると答え。ルート外はおとり |

新しい作法を足すときは `motifs.mjs` に関数を追加し、`MOTIFS` に登録する。

## Phase 2: 自己批評（Phase 1 の直後）
- 並べたとき、作法・構図・書体のうち少なくとも 2 軸が他の 1 枚と違うか
- 「円＋太いゴシック＋原色」の無難な幾何学ポスターになっていないか（それ自体が定番＝AI っぽさ）
- 謎は本当に解けるか。答えを知らない人の目で、鍵が画面内にそろっているか確かめる

---

## 絶対に避けるパターン
- グロー、光の筋、グラデーション、ぼかしによる奥行き
- 中央揃えの大見出し＋装飾円だけ、という構成
- 意味のない装飾図形（謎にも構図にも奉仕しないもの）
- 7枚で同じ書体・同じレイアウト・同じ紙色
- 判読できないほど小さいタイトル（タイムテーブル列は幅 118px）

---

## Phase 3: ハーネス

スクリプトは `scripts/`。仕様は `spec.json`（例：リポジトリの `scripts/sample-posters/spec.json`）。

```bash
python3 .claude/skills/nazotoki-visual-gen/scripts/build.py \
  scripts/sample-posters/spec.json <RAW_DIR> <WORK_DIR> <OUT_DIR>
```

| 段 | スクリプト | 内容 |
|---|---|---|
| 文字組み＋図形 | `compose.mjs` / `motifs.mjs` | Playwright で 1200×1696 に描画。行がはみ出すと自動縮小 |
| 判読性 | `compose.mjs` | 文字を消した画面を背景として、文字色とのコントラスト 4.5:1 を画素単位で判定（`legibility.json`） |
| 字組み | `compose.mjs` | 行のはみ出し・行内の折り返しを検出 |
| 一覧 | `contact_sheet.py` | 原寸縮小／**118px 実寸**／グレースケールの 3 段 |
| 公開 | `build.py` | `spec.publish` があれば JPEG（品質 86）で書き出し（PNG は紙のノイズで 1 枚 2MB 前後になるため） |

検証手順（見ずに合格と言わない）:
1. `FAIL` 行が出ないこと（判読性・字組み）。ページ内エラーは `page error:` として出る
2. 一覧シートを実際に見る：118px 段でタイトルの主要語が読めるか、7枚が散っているか
3. 謎を解いてみる：鍵だけで答えにたどり着けるか
4. アプリで確認：`?mock=1` で表の列・詳細（リング型）・My ハシゴテーブル
5. 最後に一つ削る

### 任意：画像生成を補助に使う場合
写真の背景など、図形で代えられない素材に限る。`motif.role: "background"`（全面写真）や、
`key_bg.py`（無地背景の除去・囲まれた穴の除去）→ `inkify.py`（インク数制限・版ズレ）で刷りもの化してから使う。
取得は Canva の生成画像をデザインに包んで PNG 書き出しする（サムネイルは 133px しかない）。
