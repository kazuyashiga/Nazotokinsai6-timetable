# 引き継ぎ：主催スプシ（Google Apps Script）

2026-11-18 時点。主催スプシまわりの開発を別のエージェントへ引き継ぐためのメモ。
アプリ本体（会場マップ・ルート案内などのフロント）は、引き続き別の担当が開発する。

## 1. 担当の境目

| 担当 | 範囲 |
|---|---|
| スプシ担当（引き継ぎ先） | `scripts/gas/Code.js`、`tests/gas-*.test.js`、`docs/ENTRY_SHEETS.md` |
| アプリ担当 | `src/`、`public/`、`tools/`、`promo-video/` ほか |

**境目は公開データ（data.json）の形。** `generateExportData`（`scripts/gas/Code.js`）が作る `shows[]` のキー名（日本語の列名）と「設定」のキーを、アプリ（`src/adapters/`）が読む。
キー名を変える・消すときは、アプリ担当と合わせること。列を足すだけなら、アプリは無視するので壊れない。

## 3. 検査

```bash
node --test tests/gas-entry.test.js tests/gas-entry-flow.test.js
```

- `node --test tests/` のようにフォルダを渡すと、正しく走らないことがある。ファイルを名指しする
- `gas-entry.test.js`：スプシに触れない純粋関数（行の組み立て・モード・難易度プリセット・回ごとの定員パース・時刻タイムゾーン変換・必須・指紋・状態・合わせ方）
- `gas-entry-flow.test.js`：スプシ・ドライブを簡易的にまねた環境（`Sheet` / `Book` / `Folder` クラス）で、準備から公開データ・要確認解除・難易度プリセット切り替えまで通しで動かす
  - Code.js で新しい API（例：`getNotes`、`hideColumns`、`clear`）を使ったら、まね側にも足す。足さないと、見た目系の呼び出しは何もしない Proxy に吸われ、値を返す呼び出しは壊れる
  - まねで確かめられるのは行と列の位置・振り分け・差分・ハイライト色/メモ・公開範囲まで。共有・権限・入力規則の効き方、6 分の実行上限は本物でしか分からない
- 修正のたびに「直す前のコードで失敗し、直した後に通る」検査を足してきた。この方針を続けてほしい

## 4. 守ってきた約束（崩さないこと）

- **個人情報を公開データに出さない。** 担当者名・メール・電話・運営への連絡事項は「運営用連絡先」にだけ入る。`generateExportData` はこの表を読まない。検査 `連絡先…は公開用の行に一切入らない` と通し検査の末尾がこれを見張っている
- 「取り込み元(記入用シートID)」「回ごとの定員」「【…】ボタン案内列」「1.設定」のセクション行（`■` / `▼`）は公開データに出さない（`ENTRY_NOT_PUBLISHED_HEADERS` と `generateExportData` の除外フィルタ）
- 記入用シートは担当者の Google アカウントにだけ共有する。リンクを知っている人全員には開かない
- マイドライブの直下にファイルを作らない。作る前に保存先を見せて確かめる
- 主催が「3.公演かんたん入力」に手で入れた行・直したセルを、取り込みで消さない（主催だけが直したセルは `#dbeafe` 水色＋`【主催が修正済】` メモで可視化）
- **テスト用のコピーでは「1.設定」の「GitHubリポジトリ」を空にする。** 【`4.公演一覧`へ反映＆Web公開】は最後に `exportJsonToGitHub` で本番の data.json を書き換えるため
- HOPPING FES の主催から受け取った記入シート（xlsx）は、共同制作の参考資料。ファイル本体や、中の第三者の情報（主催のメールアドレス・団体名の一覧など）をリポジトリに入れない・引用しない

## 5. 課題の対応状況

1. **本物のスプシでの実機確認（主催が `Code.js` 貼り替え後に実施）**
   - テスト用スプシの `GitHubリポジトリ` 設定は安全のため空にクリア済み、タイムゾーン（`Etc/GMT-9`）も確認済み。`Code.js` 貼り替え後に `setupDraftSheet`（または `entrySetupSheets`）を実行し、図形ボタンを案内欄横に配置すると最新UIで通せる
2. **時刻セルのずれ → 対応済み**
   - `entryTime_` および `generateExportData` がスプレッドシートのタイムゾーン（`Utilities.formatDate(v, tz, "HH:mm")`）を優先使用するように修正し、日付セルのタイムゾーン差による時刻ずれを防止した
3. **要確認の印の外れ方 → 対応済み**
   - 主催のセル値と団体のセル値が一致した次の取り込みで自動解除されるのに加え、一括解除ボタン/メニュー `entryClearCheckMarks()`（`【出展団体】「要確認」の印をすべて確認済みにする`）を追加した
4. **日程の欄を主催が書き換えた行 → 対応済み**
   - `entryMergeRows` で、未一致の日程が 1 件対 1 件で曖昧さが無い場合は 1 対 1 で結び付け、主催の日程を保ったまま重複追加しないようにした（複数行の曖昧な変更は従来通り「要確認」）
5. **記入状況を確認する → 対応済み**
   - `entryCheckCountsBySource` により、要確認セルが残っている団体は `entryImportAll` / `entryRefreshStatus` / `entryClearCheckMarks` すべてで「取り込み済み（要確認 N か所）」と表示されるようにした
6. **未使用の旧フォーム関数 → 削除済み**
   - `createEntryForm` および `importFormResponsesToDraft` を `scripts/gas/Code.js` から削除した
